# App Reverse Engineering Corpus

This page documents the current smoke corpus for the shared `reverse-engineer-app` framework.

## Current shape

The corpus is driven by:

- `.reveng/app_reverse_engineering_corpus.json`
- `scripts/run_app_reverse_engineering_corpus.py`
- `reports/app_reverse_engineering_corpus_report.json`
- `REVENGAPI.run_app_reverse_engineering_corpus(...)`
- MCP tools: `run_app_corpus` on both the simple and enterprise REVENG MCP servers

The current checked-in smoke anchors are:

- `test_samples/HelloWorld.java` via the `jvm` adapter
- `test_samples/HelloWorld.jar` via the `jvm` adapter
- `test_samples/sample_app.py` via the `python` adapter
- `test_samples/sample_app.pyc` via the `python` adapter
- `test_samples/sample_app.pyz` via the `python` adapter
- `test_samples/sample_bundle.js` via the `javascript` adapter
- `test_samples/sample_dotnet.dll` via the `dotnet` adapter

These packaged fixtures are generated reproducibly by:

- `scripts/generate_app_corpus_fixtures.py`

This is still a smoke gate, not the full world-class corpus. It now proves that the shared framework, contract serialization, and report rollup work across both source and packaged/compiled entry shapes in this checkout.

## Run the corpus

```powershell
python scripts/run_app_reverse_engineering_corpus.py
```

Run selected entries only:

```powershell
python scripts/run_app_reverse_engineering_corpus.py --entry java-helloworld --entry python-sample-app
```

## Report contract

The rollup report is written to `reports/app_reverse_engineering_corpus_report.json` and uses:

- `schema_version`
- `result_type == "app_reverse_engineering_corpus_report"`
- `summary.matrix_status`
- per-row `validation_grade`
- per-row `analysis_file`

## Current honest status

- current smoke matrix status: `pass`
